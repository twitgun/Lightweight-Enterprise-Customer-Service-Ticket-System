# 安全评审

对仓库执行一轮安全评审，按以下维度逐项检查并输出报告。

## 1. 认证与授权

- JWT 密钥是否硬编码、过期时间是否合理（`server/src/auth/`）；
- 全局守卫是否生效，`@Roles` 是否覆盖所有敏感接口；
- 资源级越权：工单详情/留言/评价接口是否校验 customerId / staffId 归属；
- 前端是否只靠菜单隐藏来防越权（不够，后端必须校验）。

## 2. 注入与数据安全

- 所有查询是否参数化（TypeORM `:param`），有无字符串拼接；
- 自定义表单字段值（fieldValues JSON）是否有类型与长度校验；
- 登录/注册参数是否防注入与暴力破解（bcrypt + 频率限制）。

## 3. XSS 与前端安全

- 用户输入（工单内容、留言、评价）渲染时是否转义（Vue 默认转义，检查 `v-html` 使用）；
- 文件/图片上传（如有）是否校验类型与大小。

## 4. 敏感信息

- 代码/配置/文档中是否泄露密码、API Key、飞书密钥、JWT 密钥；
- 日志是否打印令牌、密码或手机号等敏感字段；
- `.gitignore` 是否覆盖 `.env`、`feishu-sync/` 等敏感内容。

## 5. 输出

输出表格：`风险等级 | 位置 | 问题 | 利用方式 | 修复建议`，并给出总体结论与优先修复清单。

# 轻量企业客服工单系统（Vue 版）

基于原 PESCMS-Ticket 业务模型重新设计的前后端分离版本：**Vue 3 + Element Plus + Vite** 前端、**NestJS (Node.js)** 后端、**MySQL** 全新表结构，完全移除 PHP。

> 2026-08 扩展：已升级为“新时代”智能客服工单系统，新增 AI 智能客服、知识库问答、实时在线会话、多渠道接入、自动分配 + SLA、满意度评价、数据看板、消息通知、自定义表单与中英文多语言。

## 技术栈

| 端 | 技术 |
| --- | --- |
| 前端 | Vue 3、Element Plus、Pinia、Vue Router、Axios、Vite |
| 后端 | NestJS 10、TypeORM、JWT、bcrypt、Socket.IO（实时会话） |
| 数据库 | MySQL 8（库名 `ticket_system`，utf8mb4） |
| 可视化 | ECharts（趋势 / 分类 / 绩效图表） |
| 多语言 | vue-i18n（简体中文 / English） |

## 启动方式

1. 确保 MySQL 正在运行（root/root，或修改 `server/src/database.ts` 中的连接配置）；
2. 双击 `seed.bat` 初始化数据库与演示数据（可重复执行，已有数据自动跳过）；
3. 双击 `start.bat` 启动前后端；
4. 浏览器访问 <http://127.0.0.1:5173>。

手动启动：

```bash
cd server && npm start        # 后端 http://127.0.0.1:3000
cd web && npm run dev         # 前端 http://127.0.0.1:5173
```

## 核心业务流程

客户提交工单（待分配）→ 主管分配/转派（处理中）→ 客服留言回复、标记待客户确认 → 客户确认解决（已完结）；客户不认可时可追加留言自动回到处理中。工单状态流转、留言、分配/转派全部写入 `ticket_logs` 留痕。

### AI 配置说明

主管进入「系统设置」填写服务商接口（OpenAI 兼容格式，DeepSeek 等也可）、API Key 与模型并开启 AI；未配置时回复建议/摘要/分类使用本地规则兜底，知识库问答始终可用。

## 权限模型

三种角色：`customer`（客户）、`staff`（客服专员）、`manager`（客服主管，默认拥有客服全部权限）。后端通过全局 JWT 守卫 + 角色守卫控制接口访问，前端路由按角色渲染菜单。

## 扩展位说明（为后续开发预留）

1. **接口统一前缀 `/api/v1`**：后续微信小程序、App、开放 API 可直接复用同一套接口与 JWT 鉴权；
2. **模块化目录**：后端按业务模块拆分，新增功能只需新增 Module 并在 `app.module.ts` 注册；
3. **角色守卫可扩展**：`RolesGuard` 支持任意角色组合，新增角色只需加枚举与菜单；
4. **留痕表独立**：`ticket_logs` 与业务表分离，便于后续做满意度评价、SLA 超时提醒、报表分析；
5. **渠道 webhook**：微信/企业微信/邮件的入站端点已就绪，真实接入只需补充签名校验与凭证配置；
6. **AI 提供方可插拔**：`AiService` 统一调用 OpenAI 兼容接口，可平滑替换任意服务商；
7. **移动端（暂缓）**：接口已统一 `/api/v1` + JWT，后续可直接做小程序 / PWA / App 端；
8. **多租户（暂缓）**：`users.role` 与数据归属字段已为租户隔离预留结构。

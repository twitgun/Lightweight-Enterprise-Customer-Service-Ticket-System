# 测试策略与规范（全局生效）

## 测试基线

- 项目考核测试用例见 `08-测试用例.md`：TC001-TC024，测试 A / 测试 B 双人分工；
- 每次改动后至少回归核心闭环：客户建单 → 主管分配 → 客服回复 → 标记待确认 → 客户确认 → 评价；
- 涉及接口改动时，用演示账号（customer01 / staff01 / manager，密码 123456）验证角色权限。

## 重点回归项

| 区域 | 验证点 |
| --- | --- |
| 越权 | 未分配的客服访问他人工单返回 403；客户只能看自己的工单 |
| 状态机 | pending → processing → pending_confirm → closed，待确认时客户追加留言回到 processing |
| 实时 | 客服/客户双端打开工单，回复即时出现 |
| 看板 | 主管看板数字与列表筛选一致，统计卡可跳转 |
| 多语言/主题 | 中英文切换、深浅色切换并记住偏好 |

## 缺陷记录

- 新发现问题登记到 `08-测试用例.md` 的「测试结果记录表」（用例 ID / 实际结果 / 是否通过 / 缺陷描述）；
- 修复后在 `/fix-issue` 流程中附回归结果。
